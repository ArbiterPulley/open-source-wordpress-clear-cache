Core Web Vitals: what a page cache changes, and what it does not

LCP, INP and CLS are field metrics measured in the browser, and a page cache only touches the part of them that happens on the server. That is still the largest single component on most WordPress sites — the time before the browser receives anything — but knowing the boundary stops you buying plugins that cannot help.

CLS — layout stability, not speed

Layout shift comes from images without dimensions, late fonts and injected banners. Caching changes when the document arrives, not how it lays out. Set width and height on images and reserve space for anything that loads late.

LCP — improved by the cache and by images

The largest element is usually a hero image or the H1. A cached page shortens the wait before the HTML arrives, and correct image sizing and modern formats shorten what follows. Thistle Press Cache does both: it serves cached HTML and converts uploads, so the LCP request is smaller and starts earlier.

INP — mostly not a caching problem

Interaction to next paint is about JavaScript on the page. A heavy slider or a chat widget will dominate it regardless of caching. Measure with JavaScript disabled to see the difference; if INP is fine without scripts, the fix is choosing fewer of them.

Three numbers on the dashboard answer it: hit rate, bytes saved per request, and average generate time. A hit rate that climbs over a day of real traffic means the cache covers the pages people visit. Bytes saved moving means minification and image conversion are reaching the response. Generate time is what a visitor would have waited without the cache — if it does not drop, the pages are not being served from it.

Then confirm from outside: open the site in a private window, reload twice, and compare the server timing header before and after. A cached response is a few milliseconds of server work; an uncached one is your theme plus every active plugin. If the second reload is not markedly faster, an exclusion is swallowing the request.

Who this is for

The useful test: do you administer the site yourself, and does it run on hosting you can restart? If yes, Thistle Press Cache is the whole performance stack. If someone else owns the platform and the CDN, the plugin is a smaller piece of a larger puzzle and the counters here will tell you how much of the problem was yours to begin with.

What it does not do

No CDN. No image CDN. No edge computing, no page builder, no backup, no security firewall. Thistle Press Cache does not rewrite your theme, does not inject a dashboard banner asking for a review, and does not phone home unless the administrator ticks the box on the dashboard. If a feature needs a remote service to work, it does not belong in a cache plugin.

Frequently asked

Will a cache plugin fix my Core Web Vitals?

It reliably improves LCP by shortening server time and reducing image bytes. INP and CLS depend on your theme and scripts.

How long until the scores change?

Field data lags by up to 28 days because it averages real visits. Lab tools change immediately.

Do I need to keep the plugin enabled to keep the score?

Yes — the cached HTML is what the measurement saw. Disabling it returns the site to per-request rendering.
